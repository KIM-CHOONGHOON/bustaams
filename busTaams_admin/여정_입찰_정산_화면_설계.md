# 여정/입찰 정산 화면 설계서

본 문서는 관리자 페이지의 **여정/입찰 정산** 화면에 대한 명세 및 백업 문서입니다.

> **최초 작성일**: 2026-05-21  
> **상태**: 활성(Active)

---

## 1. 화면 개요

- **메뉴명**: 여정/입찰 정산
- **메뉴 위치**: 좌측 사이드바 — 여정/입찰현황 바로 아래
- **목적**: 회사 차원에서 일정 기간의 매출을 조회합니다. 예약 확정(CONFIRM) 처리된 건에 한해 **예약 확정일(CONFIRM_DT)** 기준으로 기간을 설정하고, 기사 입찰가 및 수수료 합계를 조회합니다.
- **대상 권한**: SUPER, MANAGER (SALES 권한은 미노출)
- **주요 대상 테이블**:
  - `TB_BUS_RESERVATION` — 예약 확정일(CONFIRM_DT), 입찰가, 수수료 (핵심 기준 테이블)
  - `TB_AUCTION_REQ` — 여정 제목, 출발지/목적지, 출발일시
  - `TB_USER` — 여행자 및 기사 이름/연락처
  - `TB_BUS_DRIVER_VEHICLE` — 차량 번호

---

## 2. 여정/입찰현황 vs 여정/입찰 정산 차이점

| 구분 | 여정/입찰현황 | 여정/입찰 정산 |
|------|--------------|--------------|
| **목적** | 전체 여행 요청 건의 진행 상황 모니터링 | 확정된 예약의 매출·수수료 집계 |
| **조회 기준 날짜** | `TB_AUCTION_REQ.START_DT` (출발일자) | `TB_BUS_RESERVATION.CONFIRM_DT` (예약 확정일) |
| **대상 상태** | 전체 DATA_STAT | `DATA_STAT = 'CONFIRM'` 만 |
| **핵심 기준 테이블** | `TB_AUCTION_REQ` | `TB_BUS_RESERVATION` |
| **하단 합계** | 없음 | 확정 건수, 기사 입찰가 합계, 수수료 합계 |

---

## 3. 화면 구성 및 UI 설계

### 3.1. 조회 조건 패널

**1행 — 확정일자 기간**
- `확정일자(From)` ~ `확정일자(To)` 날짜 범위 입력
- **기준 컬럼**: `TB_BUS_RESERVATION.CONFIRM_DT`
- **기본값**: 당월 1일 ~ 당월 말일 (컴포넌트 마운트 시 자동 세팅 및 즉시 조회)
- From 날짜는 To 날짜보다 클 수 없도록 `max` 속성 적용, 반대도 동일

**2행 — 키워드 검색**
- 조건 선택: 전체 통합 검색 / 여행 제목 / 예약자명 / 기사명
- 검색어 입력 및 초기화 기능 (날짜 조건도 기본값으로 함께 초기화)

### 3.2. 목록 테이블 컬럼

| 컬럼명 | 설명 | 데이터 출처 |
|--------|------|------------|
| **예약자** | 여행자 이름 + 연락처 | `TB_USER.USER_NM`, `HP_NO` (traveler) |
| **담당 기사** | 기사 이름 + 차량 번호 | `TB_USER.USER_NM` (driver), `TB_BUS_DRIVER_VEHICLE.VEHICLE_NO` |
| **여행 제목** | 여정의 제목 | `TB_AUCTION_REQ.TRIP_TITLE` |
| **출발지 / 목적지** | 시/구 단위 간략 주소 | `TB_AUCTION_REQ.START_ADDR`, `END_ADDR` |
| **여행 금액** | 확정된 버스기사 입찰 금액 | `TB_BUS_RESERVATION.DRIVER_BIDDING_PRICE` |
| **확정 일시** | 예약이 CONFIRM 처리된 일시 | `TB_BUS_RESERVATION.CONFIRM_DT` |

- 목록은 `CONFIRM_DT` 기준 내림차순 정렬 (최근 확정 건이 상단)

### 3.3. 하단 누적 합계 바

목록 하단에 **조회 조건에 해당하는 누적 집계**를 고정으로 표시합니다.

| 항목 | 설명 |
|------|------|
| **조회기간** | From ~ To 날짜 표시 |
| **건수 합계** | 조회된 CONFIRM 건의 총 수 |
| **총 여정금액 누적** | `SUM(TB_AUCTION_REQ.REQ_AMT)` — 여행자 요청 금액 합계 |
| **수수료 누적 (6%)** | `SUM(TB_AUCTION_REQ.REQ_AMT) × 6%` — 플랫폼 수수료 합계 |

> 데이터 유무와 관계없이 합계 바는 항상 표시됩니다 (0건일 경우 0원 표시).

## 4. 백엔드 API 명세

### 4.1. 정산 목록 조회 API

- **Endpoint**: `GET /api/admin/settlement`
- **Query Parameters**:

| 파라미터 | 타입 | 필수 | 설명 |
|---------|------|------|------|
| `confirmDtFrom` | `YYYY-MM-DD` | 선택 | 확정일자 시작 — 미입력 시 필터 미적용 |
| `confirmDtTo`   | `YYYY-MM-DD` | 선택 | 확정일자 종료 — 미입력 시 필터 미적용 |
| `searchType`    | `string`     | 선택 | `all` \| `tripTitle` \| `travelerName` \| `driverName` |
| `searchKeyword` | `string`     | 선택 | 검색어 |

- **필터 조합**: 날짜 조건 + 키워드 조건은 `AND`로 결합 (복합 조회 가능)
- **고정 조건**: `TB_BUS_RESERVATION.DATA_STAT = 'CONFIRM'` (항상 적용)

- **Response Structure** (JSON):

```json
{
  "list": [
    {
      "resId": "...",
      "reqId": "...",
      "tripTitle": "...",
      "startAddr": "...",
      "endAddr": "...",
      "startDt": "2026-05-10 09:00",
      "travelerName": "홍길동",
      "travelerPhone": "010-1234-5678",
      "driverName": "김기사",
      "vehicleNo": "12가 3456",
      "confirmDt": "2026-05-08 14:30"
    }
  ],
  "summary": {
    "totalCount": 12,
    "totalReqAmt": 24000000,
    "totalFee6pct": 1440000
  }
}
```

### 4.2. 핵심 SQL 구조

```sql
-- 고정 기본 조건
WHERE br.DATA_STAT = 'CONFIRM'
  AND DATE(br.CONFIRM_DT) >= ?   -- confirmDtFrom
  AND DATE(br.CONFIRM_DT) <= ?   -- confirmDtTo
  -- 키워드 조건 AND 추가

-- JOIN 구조
FROM TB_BUS_RESERVATION br
INNER JOIN TB_AUCTION_REQ         req      ON br.REQ_ID       = req.REQ_ID
LEFT  JOIN TB_USER                traveler ON req.TRAVELER_ID = traveler.CUST_ID
LEFT  JOIN TB_USER                driver   ON br.DRIVER_ID    = driver.CUST_ID
LEFT  JOIN TB_BUS_DRIVER_VEHICLE  v        ON br.BUS_ID       = v.BUS_ID

-- 누적 합계 (같은 WHERE 조건 사용)
SELECT
  COUNT(*)                                   as totalCount,
  IFNULL(SUM(req.REQ_AMT),        0)          as totalReqAmt,
  IFNULL(SUM(req.REQ_AMT) * 0.06, 0)          as totalFee6pct
```
