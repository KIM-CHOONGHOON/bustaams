# KG 이니시스 결제 연동 가이드 및 트러블슈팅

본 문서는 BusTaams 프로젝트의 KG 이니시스(Standard Pay) 결제 시스템 연동 과정에서 발생한 주요 이슈와 해결 방안을 기록합니다.

## 1. 결제 연동 아키텍처
- **Frontend**: React (Vite, Port 5173)
- **Backend**: Node.js (Express, Port 8080)
- **Proxy**: Vite Proxy 설정을 통해 모든 `/api` 요청을 8080으로 전달하여 도메인 불일치(CORS) 방지

## 2. 주요 트러블슈팅 및 해결 방안

### ❌ 이슈 1: V016 에러 (SignKey 불일치)
*   **원인**: 서명(Signature) 생성 시 사용된 `signKey`가 이니시스 테스트 서버의 상점 ID(`INIpayTest`)와 일치하지 않음.
*   **해결**:
    - **공식 키 적용**: `SU5JTElURV9UUklQTEVERVNfS0VZU1RS` (PC 웹 표준 테스트 전용)
    - **데이터 타입 정규화**: 금액(`price`)에서 쉼표(`,`) 등 숫자가 아닌 문자를 제거하고 문자열 타입으로 해싱 처리.
    - **해싱 알고리즘 보강**: `SHA-256` 해싱 시 `utf8` 인코딩을 명시하고, 결과값을 대문자(`toUpperCase()`)로 변환하여 정합성 확보.

### ❌ 이슈 2: V023 에러 (Domain Mismatch)
*   **원인**: 결제 요청 페이지(`localhost:5173`)와 결과 수신 주소(`returnUrl`, `closeUrl`)의 포트(`localhost:8080`)가 달라 보안 정책상 차단됨.
*   **해결**:
    - **Vite Proxy 활용**: `vite.config.js`에 프록시 설정을 추가하고, 모든 API 호출을 상대 경로(`/api/...`)로 전환.
    - **동적 URL 설정**: `returnUrl`과 `closeUrl`을 `window.location.origin` 기반으로 설정하여 브라우저 접속 주소와 완벽하게 일치시킴.
    - **중간 페이지 생성**: 결제 취소 시 부드러운 창 닫기를 위해 `public/payment-close.html` 정적 페이지 생성.

### ❌ 이슈 3: 브라우저 팝업 및 리다이렉트 차단
*   **원인**: 비동기 통신(`axios/fetch`) 후 결제창을 띄우면 브라우저가 이를 '사용자 의도 없는 팝업'으로 간주하여 차단함.
*   **해결**:
    - **Pre-fetching**: 결제 페이지 로딩 시점에 서명 데이터를 미리 가져와 캐싱.
    - **동적 폼 주입**: 사용자가 [결제하기] 클릭 즉시 순수 자바스크립트로 HTML `<form>`을 생성하고 `INIStdPay.pay()`를 호출하여 '사용자 제스처 체인' 유지.

## 3. 핵심 설정값 (테스트 환경)
- **MID**: `INIpayTest`
- **SignKey**: `SU5JTElURV9UUklQTEVERVNfS0VZU1RS`
- **인증 방식**: `SHA-256`
- **통신 순서**: `oid={주문번호}&price={금액}&timestamp={타임스탬프}`

## 4. 기사 거절 및 경매 재개 (Quotation Refusal)
결제 전, 입찰한 기사의 상세 정보(평가 등)를 확인한 후 해당 기사를 거절하고 다시 입찰을 받는 기능입니다.

### A. 비즈니스 로직
- **취소 대상**: 아직 확정되지 않은 특정 기사의 입찰 건.
- **결과**: 해당 기사와의 관계는 끊고, 경매 요청은 다시 'AUCTION' 상태로 돌려 다른 기사를 찾음.

### B. 데이터베이스 처리 (트랜잭션)
1.  **TB_AUCTION_REQ**: `DATA_STAT` -> **'AUCTION'** (경매 다시 활성화)
2.  **TB_BUS_RESERVATION**: `DATA_STAT` -> **'BUS_CANCEL'** (해당 기사 취소 처리)
3.  **TB_USER_CANCEL_MANAGE**: `CANCEL_BUS_DRIVER_CNT` -> **+1 증가** (여행자의 거절 이력 누적)
4.  **TB_SMS_LOG**: 기사님에게 취소 알림톡(SMS) 발송 예약 기록 추가

### C. 구현 상세
- **API**: `/api/reservation/refuse-driver` (POST)
- **UI**: 
    - 견적 리스트의 각 항목에 있는 [예약 취소] 버튼 연동.
    - **컨펌창**: "기사님과의 예약을 취소하시겠습니까? 취소 시 해당 기사님께 알림이 발송되며, 귀하의 기사 거절 횟수가 누적됩니다." 메시지 노출.
- **알림**: "고객님의 요청으로 견적 제안이 취소되었습니다" 문구로 기사 알림 발송.
